## 0. 一句话结论

它能跑的骨架只有四件事：**一个拦截钩子（`MC_PRE_GET_COLLECTIBLE`）+ 一个轮询（`MC_POST_UPDATE`）+ 一个渲染（`MC_POST_RENDER`）+ 一个文件桥（`Mod:SaveData` / `Mod:LoadData`）**。剩下 4700 行几乎全是"云端慢 → 预取 → 供给控制 → 统计/报告 → 兜底分类"的运维层。我们该借的是骨架和失败哲学，不该借的是预取调度、客户端 key 和闭源 sidecar。

### 1.2 为什么是"池抽取"这个点，而不是进房/底座生成后

- 底座生成时游戏先走 item pool 抽取，`MC_PRE_GET_COLLECTIBLE` 就在"已抽到、尚未真正生成"之间，**返回值直接替换**（文件头 4 行标注 M0-B 已实测）。这是唯一无需二次改写的时机。
- 由此推出它的整个架构：**决策必须提前备好**。回调里只做 O(1) 出队（2567-2586），不做任何请求、不 sleep、不忙等。全文件没有阻塞调用。
- 供给节奏在**换层**（4671-4681：新局/重载必发；在途请求 <3s 则保留不重发 4675-4678）和 **5Hz 轮询**（`POLL_EVERY_FRAMES = 6`，46 行；`poll` 2349-2351 按缺口补货）里。
- 水位表 `WANT_PER_POOL`（187-209）按池给 1-4 条；总量上限 `MAX_TASKS_PER_REQUEST = 4`（171）、首批 2 条 / 后续 4 条（60-61）、单层额度 60（181）。
- 供给安全阀三张表：房间×池（121-140）、层级×池（102-120）、房间跨池合计 10（143）。**只有真的返回了 itemId 才 +1**（2635-2638），所有回退路径不消耗额度——这个口径值得照抄。
- 明确**不做同帧同池去重**（2393-2396）：实测恶魔房同一帧会有两次合法抽取，任何去重都会吞掉第二个底座的决策。

## 2. 超时与兜底逻辑（分五层，按触发顺序）

| 层级 | 阈值 | 位置 | 语义 |
|---|---|---|---|
| 云端 HTTP 预算 | 23s（`CLOUD_TIMEOUT_SEC`） | 56 | 写进请求里给 sidecar，sidecar 自己不读 deadline |
| 请求 deadline（游戏时钟） | 26s（`REQUEST_DEADLINE_SEC`） | 55、1756、2332 | 比云端多 3s，留给 sidecar 生成"本地兜底 + 原子写盘 + 下一轮轮询" |
| 无凭据时的短超时 | `REQUEST_TIMEOUT_FRAMES/30` = 25s | 47、2287-2294 | 没配 key 就只可能走本地规则，不白等 |
| 真实时间硬兜底 | 120s（`REQUEST_TIMEOUT_REAL_SEC`） | 49、2328-2339 | 防游戏时钟冻结导致 pending 永不超时（2026-10-19 实机踩到的死法） |
| 决策存活 TTL | 120s（`DECISION_TTL_SEC`） | 74、2588-2595、poll 里 prune 2346 | 过期决策不参与替换，且在轮询里主动剔除（否则占水位不补货，2342-2345 有实测理由） |

其他失败/退化路径：

- **空响应退避**：连续 3 批"要了 N 条回来 0 条"→ 停补货 10s，避免 5Hz 请求风暴（82-83、2252-2269）。
- **连续超时降级**：同层连续 2 批云端超时 → 后续批次上限 4→2，本层内 latch 不自动恢复，换层重置（62-68、2140-2157）。
- **部分响应**：任务数 − 实际回来条数 = 缺失，**不重试**，交给下一轮水位补货（2231-2241）。
- **显式分类**：每次抽取恰好落一个分类（`aiHit` / `queueEmpty` / `requestPending` / `noBridge` / `capped` / `unsupported` / `gated` / `expired` / `invalid` / `dupBlocked` / `staleLevel`，490-516 + `tally` 2404-2436）。"桥从来没通过"单独算 `noBridge`（2529-2531），不和"预取来不及"混。
- **id 合法性**：`isValidItemId`（1156-1195）拦非数字/非整数/≤0/不存在/未解锁，并额外拦 `TAG_QUEST`、贪婪/挑战/每日的禁用 tag。
- **模式门禁**：每日 / 挑战 / 贪婪一律不改道具，四个检查点（生命周期 2298、发请求前 1680、收响应前 2096、抽取回调最终裁决 2464）；进入边沿清队列 + `epoch++` 作废在途（864-877）。
- **文件损坏**：`readDoc` 解析失败累计 `parseFail`（1434-1443）；若手上还有在途请求，说明文件被写坏 → 推进 epoch 重发（2302-2308）。
- **兜底哲学（最值得学的一条）**：任何不确定性一律 **return nil 走原版**，从不"猜一个差不多的"；且每个失败都有名字、都进得到报告。它甚至把"AI 说 A、实际生成 B（被别的 mod 覆盖）"单独计数（3349-3362）。

## 3. 文件桥（传输层）怎么做的

- **写盘唯一通道是 `Mod:SaveData`**（1916 写请求、1555 写配置），读是 `Mod:LoadData`（1435）。作者注释写明原因：Lua 沙箱只有这一个写盘口（1452-1454）。
- 协议文件就是那个存档数据文件（注释里出现 `saveN.dat`，1452、981），**sidecar 直接读同一个文件**，靠 `epoch` / `turn` / `writer` 三个字段避免双写 ping-pong（16-18、1862-1908）。
- 栅栏规则：只有 mod 能 `epoch++`（317、1741-1744）；响应回来先校验 `epoch` 与 `forTurn`，不符直接丢弃（2201-2213），迟到结果不覆盖文件（2323-2339）。
- 逐条回查：每个任务有 `decisionId`（1758-1786），响应里按 id 回查，**不属于本次请求 / 池不符 / 批内重复**都拒绝（1966-1991）；允许 sidecar 自己标 `valid=false` 预验证失败（1987-1991）。
- 跨层：请求发出时的层记在 `genLevelKey`（1773、2009-2010），消费时可选择严格拒绝旧层决策（2597-2609，开关 97）。
- 对我们：**"写者唯一 + 单调序号 + 迟到丢弃"可以直接搬**；但把协议塞进存档、还必须用 `SaveData` 这个唯一口，是它的环境限制，不是我们的。

## 4. 气泡 UI 怎么画（三层降级 + 一堆实机坑）

### 4.1 主路径：自绘（`MC_POST_RENDER` 里画）

- 三件套：`bubble.anm2`（白底圆角 + 描边 + 尾巴）/ `bubble_r.anm2`（尾巴镜像，2732-2737）、`char.anm2`（立绘）、`Font` 加载中文 `.fnt`（2885-2891）。渲染入口 `renderThoughtChar` 3109-3169，文字排版 `drawThoughtText` 3052-3107。
- 坐标口径（作者反复实机查证，2948-2970）：
  - 布局常量写在 **1280×720 设计空间**（2712-2730：气泡 958,220 / 290×150，尾巴 40，内边距 26，立绘 1098,365 / 150×150）。
  - `Sprite:Render` 在 `MC_POST_RENDER` 里吃**屏幕坐标**，与 `Isaac.GetScreenWidth/Height()` 同一套；本机返回的是内部渲染分辨率 **512×288**，不是窗口像素（2560×1440）。
  - 所以设计坐标 × (sw/1280, sh/720) 喂 Sprite；ImGui 用窗口像素，需要单独的换算系数（`ImGuiToWorld` + `WorldToScreen` 实测，2979-3041，实测 k≈5，常数兜底 5.0）。
- 文字排版（3052-3107）：字号依次试 0.78 / 0.70 / 0.62 / 0.54，最多 4 行，行高 = 字宽×1.18；**按 UTF-8 字符切行**（按字节切会把中文切碎）；用 `Font:GetStringWidthUTF8("中")` 量宽后水平居中，垂直居中有个坑：`DrawString*` 的 y 是行顶，不要再 + 半行（3094-3096）。
- 颜色：AI 用深蓝、规则兜底用灰（3098）；`[AI]` / `[规则]` 前缀是**主信号**，颜色只是辅助（2750-2757、2795-2806）。
- 字体候选按"官方中文优先"排序（`resources-dlc3.zh/...` 21368 字形 → `resources.zh/...` → 本地第三方图集 7148 字形仅兜底），作者自己标注了第三方素材**上架有授权问题**（2879-2891）。
- 显示时机（2682-2690）：响应到达 → 只入队；被消费 → 记 `hitsPending`；**`MC_POST_PICKUP_INIT` 同帧（≤2 帧）同 id 核验通过 → 才弹**；被覆盖/过期/被拒/换层 → 永不弹。停留 6s，按**真实时间**到期（暂停里也消失，2691、3253-3260）。理由：提前弹的结果是"AI 说它选了硫磺火，游戏里出现的是别的东西"。

### 4.2 降级路径

字体或气泡底图任一不可用 → 退回 **ImGui pinned 窗口**（3210-3248，窗口在 4081-4102 创建，需 `SetWindowPinned`）；再不行 → 只写日志（3213-3216）。

### 4.3 现成的坑（我们照做时能省几轮实机）

- `Sprite:Load` **只认 anm2**，裸 PNG 会被静默忽略（2810-2812）。
- 本机 `Sprite` 没有 `SetLayerScale` / `SetScale` 方法，但有 `Scale` 属性（2824-2831）。
- `ImGui.ImGuiToWorld` 是 **void**：原地改传入的 Vector，写成 `local w = ...` 永远拿 nil（2973-2976）。
- 同一个回调 id 上重复 `AddCallback`（在测试桩里）会静默丢掉前一个函数（649-651）；所以 HUD 文字和立绘合并进了同一个 `onRender`，并靠顺序保证不互相盖。
- `local` 前向声明必须在**使用点之前**，否则调用点捕获到的是全局 nil（626-636，作者踩过两次）。
- `Font:Load` 成功但"字宽全是 0"= 图集页不全（.fnt 声明 pages=2 只拷了一页，2872-2877）；所以判成功要**实测字宽**，不能只看有没有抛错。
- `Sprite:Load` 走 XML 解析器，喂错文件会触发原生断言、`pcall` 拦不住（会 minidump），所以素材加载推迟到"第一次要显示时"（4106-4109）。

### 4.4 我们该怎么办（更小）

不上 anm2/PNG/立绘：**一个半透明圆角矩形 + 多行 `Isaac.RenderText` 或 `Font`（官方中文字体）** 就够表达"理由"。位置固定左下角或右侧，按内部渲染分辨率换算；中文一律用官方 `resources-dlc3.zh` 字体，不分发任何字体图集。核验后弹的规则照抄（先核验，后展示）。

## 5. 不可借鉴的部分

### 5.1 API Key 放在客户端（红线）

- 它的 `cfg.apiKey` 在游戏内 ImGui 输入框里输入（3965-3980），经 `Mod:SaveData` 写进**存档数据**（1452-1454），再随每个请求下发到 sidecar（`configForWire` 1466-1483、1869），sidecar 落盘 `llm_config.json`。
- 它做了打码、不回显、不进回放（`maskKey` 710、日志 1560-1562、响应只回 `hasKey` 2182-2196），这些**做法本身是对的**；但根治办法是**别让 key 进客户端**。
- 我们：mod 侧协议里**没有 key 字段**、不读不写不转发；key 只在 DSH 侧（插件进程的环境/自身配置），mod 永远不知道有 key。

### 5.2 开局自启 + 常驻后台

- 首次双击 `tools/StartAIConnector.cmd`：解压 `bridge.zip` 到 `%LOCALAPPDATA%\AIItemControl\payload` → 启动 `AICtrlBridge.exe` → **该 exe 自动安装自己并注册开机自启**（`连接器说明.txt` 第 7-11 行；`main.lua` 4803 "之后开机自动启动"；`metadata.xml` 第 9-11 行）。之后一直后台常驻。
- 副作用：玩家机器上多一个永久自启的后台进程，且它持有 API Key、能读游戏存档文件。
- 我们：**不注册任何自启、不常驻、不打包 exe**。DSH 插件在会话里按需跑；mod 只读写约定目录的本地 JSON，关游戏就结束。

### 5.3 闭源二进制（9.4MB PyInstaller）

- `tools/bridge.zip`（9,436,341 B）里是 `AICtrlBridge.exe`，PyInstaller 打包、无源码。它同时负责：读协议文件、调云端、写回、存 key、注册自启、开本地设置页。
- 结果：**无法审计 key 去哪了、是否上传了对局数据**，也无法验证它的"本地兜底"是否真的本地。对开源项目这是硬伤。
- 我们：全源码（MIT）、无网络、无二进制；决策由 DSH 侧的 agent 调用完成，链路每一步都可读。

### 5.4 架构层面不建议照搬

| 它的做法 | 为什么它必须这么做 | 我们为什么不抄 |
|---|---|---|
| 全层预取 + 水位 + 16 池 + 3 类上限 + 懒预取/空转熔断（102-209、1279-1334） | 云端一次 10-20s，来不及在回调里等，只能提前囤货；囤多了又要防浪费 | 我们第一版走**需求驱动**：底座要了就问、问不到就走原版。代价是首个底座原版，换来代码量少一个数量级 |
| `epoch` / `turn` / `decisionId` 三层生命周期塞进存档文件 | Lua 沙箱只有 `SaveData` 一个写盘口 | 我们用独立目录的 `state.json` / `decision.json`，写者唯一 + 单调 `ts`，不需要把协议塞进存档 |
| 160 条候选目录 + 品质轮换 + 去重硬规则（975-1131、85-90） | 模型会乱给、会重复给，只能靠调度和硬规则补 | 我们靠**协议约束**（只准在候选池里选）+ 校验（非法即兜底），先不做调度层；去重列为 v2 |
| 游戏内 ImGui 配置窗口（3933-4114） | 玩家不会改 JSON | 配置在 DSH 侧，mod 零配置 |
| 4805 行单文件 + 30+ 函数 + 报告/回放/统计体系 | 它已经是一个长期维护的产品 | 我们 t3 是几百行的最小闭环；报告只留 `log.txt` 一行一条 |

## 6. 我们自己最小可行的钩子集合（建议）

### P0（t3 必须，4 个）

| 钩子 | 用途 | 关键约束 |
|---|---|---|
| `MC_PRE_GET_COLLECTIBLE`（62） | 唯一改写点：有合法决策就返回 `id`，否则 `nil` | **同步返回，绝不等待**；出队 O(1)；非法 id 一律 nil 并记 `reason=invalid` |
| `MC_POST_UPDATE` | 5Hz（每 6 帧）轮询 `decision.json`；跨帧截止计帧 | 用 `Game():GetFrameCount()` 计帧，不忙等、不 sleep；文件读写全 `pcall` |
| `MC_POST_RENDER` | 气泡：矩形 + 多行中文 + `[AI]/[规则]` 前缀 | 只用官方中文字体；坐标按 `GetScreenWidth/Height` 换算；字体不可用就不画（别画半截） |
| `MC_POST_NEW_ROOM`（可选 `MC_POST_NEW_LEVEL` 二选一） | 进房写一次 `state.json`（房间类型/层/血量/道具），给插件预热与"进房事件" | 只写不请求；`pcall` 包住；不阻塞 |

### P1（自检/调试，2 个）

| 钩子 | 用途 |
|---|---|
| `MC_POST_PICKUP_INIT` | 核验"返回的 id == 实际生成的底座"（同帧 ≤2 帧）；核验通过才弹气泡；不符记 `overridden` |
| `MC_EXECUTE_CMD` | `isaac_agent status|dump|on|off`，**必须 `return nil`**（非 nil 会崩游戏，4564） |

### P2（收尾，1 个）

`MC_POST_GAME_END`：清队列/pending、重置本局去重集合、写一行汇总日志。

### 明确不注册

- 任何 ImGui / Font 自绘素材（除非以后要做立绘）。
- 任何"生成前"的伪钩子——`MC_PRE_GET_COLLECTIBLE` 就是最早的可用点；想在底座出现后改，只能 `Morph`，会有可见的换货闪烁，不作为主路径。
- 优先级：`AddPriorityCallback` 可用，但**先不抢优先级**。本机 `zhenzhenrishang` 等 mod 也挂了 62（如 `mods/zhenzhenrishang_.../scripts/item/cunmu.lua:56`），多个 mod 同时返回 id 时谁赢需要实测；第一版用默认优先级，测完再决定 EARLY/LATE。

## 7. 给 t1 / t3 的三个硬提醒（会改设计的那种）

1. **`MC_PRE_GET_COLLECTIBLE` 里不能等 1500ms。** 它必须当帧返回；t3 里"最长 1500ms"只能理解为**"请求 → decision.json 落盘"的预算**，实现上要么提前请求（预取），要么当帧返回 nil、之后用 `Morph` 补写（有闪烁）。建议第一版：**进房/首次需求时发请求，回调只吃已有决策；没货就走原版**，把 1500ms 记成"决策有效期/超时判定"而不是"回调内等待"。
2. **写盘口要先实测。** 参考实现说 Lua 沙箱只有 `Mod:SaveData` 一个写盘口（1452-1454），它因此把协议塞进存档文件。t3 要求"原子写 `%LOCALAPPDATA%\IsaacAgent\state.json`（.tmp→rename）"——纯 REPENTOGON Lua 是否有任意路径文件 API 需要 t3 第一天就验证；若没有，退路是：(a) mod 用 `SaveData` 写、DSH 插件去读那个存档数据文件；(b) 只让插件写 `decision.json`、mod 只读（我们协议本来就是单向的，这条最省事）。
3. **协议字段可以借它的**（不是抄代码，是抄契约形状）：`decisionId`（逐条对账）、`genLevelKey`（区分"哪层生成的"）、`source`（`llm` / `rule`，**不由"理由是否为空"推断**）、`valid=false` + `reasonCode`（对端预验证失败要显式）、允许**部分响应**（缺条目不算错，下一轮补）、每次抽取**恰好落一个分类**。这几条正好补 `docs/protocol.md` 的兜底语义。
